# 공통 페이지 지침 (pages/) — 콘텐츠 설계

> 루트 `../CLAUDE.md`의 공통 규칙 위에 적용된다. 8단계(사이트 폴리시)의 콘텐츠 확충은 이 문서가 설계도다.
> 구현 위치: 화면은 `src/shared/ui/views.tsx`, 문구는 전부 `../locales/`(스키마는 `../locales/CLAUDE.md`).

## 여기서 다루는 화면
특정 모델·카테고리에 속하지 않는 공통 화면 전부 — **홈** + 상단 탭 3개(**소개 about · 학습 구조 learn · 제작자 의도 intent**) + **푸터**.

## 상태: 구현 완료 (8-b 푸터 · 8-c 콘텐츠)
아래 섹션 구성대로 구현돼 있다 — 홈(쇼케이스·신뢰 레이어), about/learn/intent(섹션 배열), 푸터. 콘텐츠를 수정할 땐 이 설계와 `../locales/`의 4개 언어를 함께 갱신할 것. 문구는 제작자가 계속 다듬는 것을 전제로 한 초안이다.

## 톤 가이드 (전 페이지 공통)
- 차분하고 정확하게. 과장("혁신적인", "최고의") 금지, 이모지 금지, 느낌표 절제.
- 정밀 계측기 컨셉에 맞게: 수치·구체적 사실로 신뢰를 만든다 ("8층 DRAM을 50μm 두께로" > "놀라운 기술").
- 어려운 용어는 첫 등장에서 한 줄 풀이. 입문자가 1차 독자, 전문가가 읽어도 틀린 곳이 없어야 한다.
- 문단은 짧게(2~3문장). 섹션 하나에 메시지 하나.

---

## 홈 (Home) — 섹션 구성 (위에서 아래로)
1. **hero** — 현행 유지(카피만 점검). 우측 CSS 스택 모티프 유지.
2. **how (3단계)** — 현행 유지: 회전 → 분해 → 학습.
3. **카테고리 쇼케이스 (신규)** — 8개 카테고리 그리드. 각 카드: 모티프 + 카테고리명 + 모델 수("3개 모델 · 2개 학습 가능" — 카탈로그에서 계산, 하드코딩 금지). 클릭 시 해당 카테고리로.
4. **신뢰 레이어 (신규)** — "정확함"을 한 섹션으로: 실제 구조·치수 기반 모델링 / 부품마다 역할·수치 설명 / (예정) 출처 링크. 3개 항목, 짧게.
5. **footer (신규)** — 아래 푸터 사양.

## 소개 (about) — 섹션 구성
1. **무엇인가** — 한 문단: 기술 제품을 3D로 분해하며 배우는 교육 도구.
2. **누구를 위한 것인가** — 3항목: 진로를 탐색하는 학생 / 인접 분야를 이해하려는 엔지니어 / 뉴스 속 기술(HBM·칩렛…)이 궁금한 사람.
3. **무엇이 다른가** — 3항목: 글·영상이 아닌 직접 조작(회전·분해) / 부품 클릭 → 역할·수치 / 같은 조작감으로 전 분야 확장.
4. **어떻게 만드나** — 한 문단: 공개 표준·백서 기반 모델링, 단순화한 부분은 명시(신뢰 레이어). 무료로 사용.

## 학습 구조 (learn) — 섹션 구성
1. **3단계 흐름** — 회전/분해/학습 각각 한 문단으로 확장(어떤 조작인지 + 왜 그 순서인지).
2. **정보 패널 읽는 법** — 부품을 누르면 보이는 것: 태그·치수 → 한 줄 요약(lead) → 자세히(detail) → 핵심 3가지(facts). 화면 구조와 같은 순서로 설명.
3. **쉬운 말 ↔ 정확한 수치** — 비유로 시작해 실제 용어·치수로 들어가는 서술 원칙. 특정 분야 부품명을 예시로 박지 말 것.
4. **분야별 추천 순서 (안내만)** — "각 분야 화면 상단의 추천 순서를 따라가라"는 안내까지만. **구체적인 순서(HBM→GPU→CPU 등)는 여기 두지 않는다** — 카탈로그 `CategoryEntry.guide`에 두고 카테고리 화면이 콜아웃으로 표시한다.

## 콘텐츠 레벨 구분 (중요)
- **공통 페이지(여기)** = 분야 중립. 사이트가 무엇인지·어떻게 배우는지만. 특정 분야의 모델명·순서·용어를 본문에 넣지 않는다(분야 나열 정도는 허용).
- **카테고리 화면** = 그 분야의 한 줄 소개(`CategoryEntry.intro`) + 추천 학습 순서(`CategoryEntry.guide`, 있으면).
- **모델 화면** = 개요·사양(카탈로그) + 부품 설명(data.ts).
새 분야를 추가할 때 공통 페이지는 손대지 않아도 되는 구조를 유지할 것.

## 제작자 의도 (intent) — 섹션 구성
1인칭 유지, 짧은 에세이 톤(섹션 제목 없이 문단 흐름도 가능):
1. **출발점** — "열어서 직접 보면 이해가 빠르다"는 믿음(현행 문구 재활용).
2. **무엇을 약속하나** — 정확함을 우선한다 / 단순화한 곳은 숨기지 않는다 / 무료로 유지한다.
3. **어디로 가나** — 카테고리·모델을 계속 늘린다, 한 줄 로드맵. 서명("— 토론토에서, 제작자") 유지.

## 푸터 (전 화면 공통)
- 구성: 브랜드 + 한 줄 설명 / 탭 링크(소개·학습 구조·제작자 의도) / 카테고리 링크 / 저작권 줄("© YYYY STRATA · 교육 목적의 단순화된 모델입니다").
- 모델 면책 한 줄은 신뢰 레이어의 일부 — 빼지 말 것.
- 시맨틱 `<footer>`, 사이드바와 겹치지 않게 본문 폭 기준.

## 규칙
- 모든 문구는 `../locales/`의 다국어 키. 페이지 본문 하드코딩 금지. 섹션 구조 스키마는 `../locales/CLAUDE.md`.
- 레이아웃·톤은 시안 `homepage-mockup-v2.html` 기준(좁은 본문 폭, 모노 eyebrow + 큰 제목 + 차분한 본문). 새 섹션도 같은 문법으로.
- 통계·개수(모델 수 등)는 카탈로그(`shared/catalog.ts`)에서 계산해 표시 — 숫자를 문구에 박지 말 것.
- 문구 초안은 클로드가 쓰되 **제작자가 다듬는 것을 전제**로 자연스러운 초안을 만든다. 4개 언어 동시 작성.
